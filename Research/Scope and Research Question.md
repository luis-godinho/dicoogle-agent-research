# Scope and Research Question — v0.1

**Status:** Draft proposal for supervisor review; not a claim about implemented capabilities.

## Problem
Medical-image workflows combine object selection, data requirements, tool capabilities, parameters, ordering and authorization. A plausible plan generated by a language model does not establish that its data bindings and preconditions are technically valid.

## Candidate contribution
A versioned DICOM-native model for references and tool contracts; a typed pipeline representation with explicit bindings; deterministic structural and semantic validation rules; and a controlled test set with expected outcomes. Novelty remains to be established through a broader related-work review.

## Main research question
> To what extent do DICOM-native contracts and deterministic semantic validation improve the composition of technically admissible pipelines by an LLM-based planner, compared with natural-language tool descriptions and structural-only validation?

“Technically admissible” means accepted under the specified contracts, context and policies. It does not guarantee future execution success, clinical suitability, or universal security.

## Included
- A small, approved, versioned tool catalog.
- DICOM references at study/series/instance levels; the initial use case operates on a resolved series.
- Metadata inspection, compatibility assessment, and internal report generation.
- Explicit plan nodes, dependencies, and input bindings.
- Structural, type, parameter, precondition, access, effect, and approval checks.
- Synthetic fixtures first; public or appropriately anonymized data only with approval.
- Mock adapters first; integration only after target Dicoogle interfaces are confirmed.

## Excluded from v0.1
Clinical diagnosis, pixel processing, arbitrary LLM-generated code, external export, archive mutation, de-identification, distributed orchestration, automatic Next/v3 fallback, and claims that any deployment exposes a particular DICOMweb interface.

## Evaluation outline
Separate the effect of contracts on planning from the effect of validation on acceptance. Compare natural-language descriptions and structured contracts over the same requests/context. Compare structural-only and semantic validation over the same candidate plans. Include reviewed deterministic templates as a baseline. Measure valid candidates before filtering, invalid accepted plans, valid rejected plans, per-rule detection, task completion, clarification behavior, latency, and provenance completeness.

## Relation to scholarship plan
The initial work emphasizes the data/tool model, catalog, and validated planner; execution and provenance are bounded initial work, not an assumption that a full production engine is due now. See [[Reference Use Case]] and [[Evaluation Protocol]].
